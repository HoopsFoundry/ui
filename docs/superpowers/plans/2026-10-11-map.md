# Plan: Map (Leaflet + OpenStreetMap)

Spec: `docs/superpowers/specs/2026-10-11-map-hallenkarte-design.md` (Abschnitte „Datenschutz und Kachelserver“ und „Map“). Branch `feat/map`. Die Hallenkarte (VenueCard) ist nicht Teil dieses Plans.

## Schritte (kleine Commits)
1. Abhängigkeit: `leaflet` (dev + optionale Peer-Abhängigkeit), `@types/leaflet` (dev), Exports `./svelte/Map`, `./map.js`.
2. `js/map.js` + `.d.ts`: `mapLinks`, `formatCoords`, `validTileUrl`, `boundsOf`, `isCoord` plus gemeinsame Hilfen (`mapItems`, `initialView`, `placeholderPins`, `mapText`); Tabellentests.
3. `js/map-leaflet.js`: gemeinsamer Controller (dynamisches `import('leaflet')`, Marker als `L.divIcon` mit Inline-SVG aus DOM-Aufrufen, Reaktivität, Fehlererkennung, `remove()`), geteilt von Svelte und React.
4. CSS `dss-map*`, Komponenten `svelte/Map.svelte`, `react/Map.tsx`, Manifest, Export, Tests mit gemocktem Leaflet, SSR-Parität.
5. Doku `Components/Map` (MDX, Stories, Code, Beispiele, Spielwiese, Proxy-Rezepte), Introduction, storySort, README, CHANGELOG, Vorschau-Import von `leaflet.css`.
6. Mutationstests, Browser-Prüfung mit abgefangenen Kacheln, Merge von `main`.

## Entscheidungen
- React-Export heißt `MapView` (Datei `react/Map.tsx`), um das JS-Global `Map` nicht zu überdecken; Svelte-Datei `Map.svelte` (Import als `MapView` empfohlen). Doku-Seite heißt „Map“. Das Parität-Manifest kennt dafür das Feld `export`.
- Zoom-Schaltflächen, Quellenangabe, Platzhalter und Fehlerhinweis sind eigenes Markup der Komponente (SSR-fähig, axe-prüfbar); Leaflet liefert nur Kacheln, Marker und Gesten (`zoomControl: false`, `attributionControl: false`).
- Demo-Kacheln in Storybook: lokales PNG, Adresse über `new URL(png, location.href).pathname + '?z={z}&x={x}&y={y}'`; `validTileUrl` bleibt streng (keine Sonderoption).
- Fehler „Kacheln blockiert“: Zähler über `tileload`/`tileerror`, Auswertung bei `load` der Kachelebene: keine Kachel geladen und mindestens ein Fehler.
