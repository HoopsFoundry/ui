# Überschriften

Jede Komponente mit Titel (Table, ScheduleTable, ScheduleGrid, PlayerCard, TeamCard, EmptyState, PlayByPlay, Modal) gibt eine Überschrift aus. Zwei Dinge sind getrennt: die **Ebene** (das Element `h2` bis `h6`, sie gliedert die Seite für Screenreader und Sprungmarken) und die **Größe** (das Aussehen, hängt an Klassen und Tokens). Keine Komponente gibt eine `h1` aus: die gehört der Seite der App.

## Ebene ist nicht Größe

Die Größe einer Komponentenüberschrift hängt an einer Klasse (`dss-frame-title`, `dss-pc-nm`, `dss-team-nm`, `dss-empty-title`, `dss-pbp-title`, `dss-m-title`), nie am Elementnamen. `h2`, `h3` und `h4` sehen deshalb gleich aus. Wer eine andere Größe will, ändert das Token (siehe unten), nicht die Ebene. Wer eine andere Ebene will, ändert die Gliederung, nicht die Größe.

## Rangfolge der Ebene

Eine Titelkomponente wählt ihre Ebene in dieser Reihenfolge:

1. `titleAs` an der Komponente (`'h2'` bis `'h6'`),
2. sonst die Ebene aus dem nächsten `HeadingLevel` darüber,
3. sonst `h3`.

## Größe über Tokens

Die Tokens sind absichtlich nicht vorbelegt. Ohne Wert gilt je Komponente der bisherige Wert aus der Tabelle unten; so ändert sich ohne Eingriff nichts. Setzt du ein Token an einem Element (etwa an einem Container), gilt es für alle Titel darin. Komponentenspezifisch vor global: `--hoops-frame-title-size` und `--hoops-card-title-size` schlagen `--hoops-title-size`.

## HeadingLevel

`HeadingLevel` gibt den Titelkomponenten im Inhalt eine Ebene vor, ohne dass jede Komponente ein `titleAs` braucht. Es wirkt nur auf Komponentenüberschriften, nicht auf eigenen Text der App, und ändert nur die Ebene, nicht die Größe.

### Verschachteln mit by

`by` zählt vom übergeordneten `HeadingLevel` aus weiter. Ein Bereich muss so seine absolute Ebene nicht kennen, er zählt einfach eine Stufe tiefer; verschachtelte Bereiche bleiben in der Gliederung richtig:

### Modal

Das Modal hat ein `titleAs` (Standard `h2`) und gibt seinem Inhalt und seinem Footer die nächste Ebene weiter: Titel `h2`, Titelkomponenten im Inhalt `h3`; bei `titleAs="h4"` bekommt der Inhalt `h5`, die Ebene wird auf `h6` begrenzt. Ein eigenes `HeadingLevel` im Inhalt oder ein `titleAs` an der Komponente gewinnt. Ein `HeadingLevel` um das Modal ändert den Titel des Modals nicht. In React gilt das auch im Radix-Portal (der Kontext bleibt erhalten). Das Portal hängt das Modal aber an `body`: ein Größen-Token, das nur an einem Container gesetzt ist (etwa `--hoops-title-size` an einer Seitenleiste), erreicht den Titel eines React-Modals deshalb nicht; die Svelte-Fassung rendert inline und erbt es. Setze das Token für Modals am `:root` oder am `body`. Das Modal ist die einzige Komponente, die selbst Inhalt mit Titelkomponenten aufnimmt und die Ebene weitergibt; die Card tut es nicht, dort setzt du `HeadingLevel` oder `titleAs`.

### Vanilla-HTML

Ohne Svelte oder React gibt es keinen Provider: Du schreibst das Element selbst ins Markup (`h2` bis `h6`) und behältst die Klasse (`dss-frame-title`, `dss-pc-nm` …). Der Standard der Komponenten ist `h3`; das erste Beispiel oben zeigt das Vanilla-Markup. Die Größe ändert sich dadurch nie.

### Eigene Überschrift in React

`useHeadingLevel()` liefert die Ebene (2 bis 6) an der Stelle im Baum; ohne `HeadingLevel` darüber `3`. Mit `headingTag()` aus `@bbv/dss-design-system/heading.js` wird daraus das Element:

### Reine Funktionen

`@bbv/dss-design-system/heading.js` ist ohne Framework nutzbar. Zahlen außerhalb von 2 bis 6 werden begrenzt, alles ohne Ganzzahl (`NaN`, `3.5`, `null`, `undefined`) ergibt den Standard 3; eine Zeichenkette aus Ziffern (`'4'`) gilt wie die Zahl, andere Zeichenketten (`'h4'`) nicht. Das hilft in Svelte-Vorlagen, wo `level="4"` eine Zeichenkette ist.
